# 通行证调价导入

优先使用已由管理员确认的当期原图位置参照。首次建档保留商品外框、原图地址和角色；保存后形成位置对照。后续同版式调价图片由管理员选择对应参照，逐一返回带符号标注的小框，系统用标注中心落入的唯一商品区域关联角色。多个框重叠、位置不符或图片重排时须复核，不得选最近的框硬配。跨版式、裁剪、旋转的图片应重新建参照。位置只能辅助角色归属，金额仍读取本次图片，不能沿用上次金额。

看见通行证商品页上的加减价标注时，逐个关联分盒、角色及标注。印刷字、手写字均需读取；结合标注覆盖位置、引线、角色名称和相邻分片判断归属，同角色的正反两件通常是一对，不重复生成两条调价。

返回通行证商品的 `boxId`、`character`、`adjustment`（带符号数值）、`adjustmentText`（原始标注）、`adjustmentStatus`（`clear`、`uncertain`、`none`）。例如明确的“+40”返回40，“-16”返回-16。数字、正负号、角色归属都明确才用clear；无标注用none及null；手写看不清、符号缺失、归属有歧义或单位不明时用uncertain及null，并将疑问写入questions，不能以默认0冒充识别结果。保留原始标注方便复核。

不能仅凭红蓝颜色推定正负号，不能把单抽价、整盒价、数量、型号当成调价。不强制把所有角色调价凑成零，也不把单抽／单件金额自行换算成每对。均价仍由用户统一填写，当前任务只提取每对调价。

已收录老分盒也必须返回图中有调价的角色条目；boxIds只能替代角色名录，不能替代调价读取。逐片检查全部商品，其他单领、特典照常识别。仅识别文字模式也读取清楚的加减价标注，但不根据外观猜角色。

先读分盒号，再使用系统提供的该盒角色名单核对。名单的顺序不代表图片的排列顺序；不得按顺序硬配，不得以熟悉的旧角色替代新角色或异格。角色身份不清楚时保留标注和位置待复核。数字逐字读，尤其区分5和6、1和7，不按常见价位或加总结果修正数字。服务端发现角色不属于该盒或标注含糊时会针对该盒复核一次，其他单领和特典保留首次结果。

重复导入时保留已确认的识别结果与人工调价；此前未识别到调价的默认项，可以补入本次明确读到的调价，不新增同一角色商品。
